# 错误分类与重试语义

`client-core` 的失败都收敛到 [`ClientException`](../client-core/src/main/kotlin/org/pickaxe/client/ClientException.kt)
的密封子类；每个子类对应一个可区分的处理路径。本表是“这个错误能不能重试”的唯一定义，
调用方不要靠 `message` 文本判断。

| 类型 | 含义 | 可重试 | 处理建议 |
| --- | --- | --- | --- |
| `ConnectFailed` | TCP 未建立：地址不可达、端口未监听、DNS 失败 | 是 | 换地址/端口重试；指数退避，避免打爆目标 |
| `NetworkFailure` | 连接建立后的网络错误：读超时、连接重置 | 是 | 会话已不可用；丢弃 `Session` 后重新 `connect` |
| `ServerDisconnected` | 服务端主动结束会话（白名单、人数上限、维护、踢人） | 通常否 | 按 `reason` 处理；只有运维恢复后再重连 |
| `ProtocolFailure` | 状态机不符、包解码失败、版本/依赖不匹配 | 否 | 修版本或依赖；重试只会复现同一个错误 |
| `Timeout` | 等待某个阶段超时（状态查询、登录、补全等） | 视场景 | 只读查询可重试；`awaitPlay` 超时说明连接已不可用，应重建会话 |
| `EventOverflow` | 事件缓冲写满，会话已按 M3 的保守策略终止 | 否（同一消费者） | 先修消费速度；修好后新建会话，不要复用旧会话 |
| `Closed` | 对已关闭的会话继续操作 | 否 | 调用方状态错误；关闭后只应读取最终状态 |

## 判定原则

- **错误发生在会话建立前**（`status` 查询、`connect` 的 TCP/登录阶段）：可以换参数重试。
- **错误发生在会话内**：`Session` 已经终止或即将终止，重试意味着新建连接，而不是重发某个调用。
- **协议错误与事件溢出不是网络抖动**：重试不会改变结果，必须先改变版本、依赖或消费速度。
- 服务端主动断开与超时的区别在责任方：前者是服务端决定，后者可能是本端等待策略太短。

## 不作承诺的部分

- 不提供自动重试：重连涉及凭据、地址与业务状态，属于宿主的策略。
- 不保证“重试一定成功”或重试次数；本库只保证错误分类稳定、终止事件恰好一次。
- 0.x 阶段新增子类属于允许的变更，调用方应保留未知分支的兜底日志。
