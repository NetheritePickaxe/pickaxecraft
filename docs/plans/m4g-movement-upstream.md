# M4g 实施记录：移动上行

日期：2026-11-04
提交：（见仓库历史）
前置：M2（出生链路）、M4b（实体跟踪，移动包的相对量语义已在接收方向验证）

## 1. 目标

让调用方可以不接触包类型就把“我在哪、我朝哪”告诉服务端，并且**只发变化的部分**：
协议把移动拆成四个包（仅坐标、仅朝向、坐标+朝向、仅状态），字段缺省时服务端沿用上一状态。
选错包不会报错，只会表现为“朝向对了但人没动”或“人动了但朝向被重置”。

## 2. 交付内容

### 2.1 公共 API（`client-core`）

- `Session.moveTo(position: Position, onGround: Boolean = false)`：把位置与朝向一起声明给服务端。
- `Session.look(yaw: Float, pitch: Float, onGround: Boolean = false)`：只改朝向；协议里的 `rot`
  包不带坐标，因此不要求已经收到过位置同步。
- 两者都只在 `PLAY` 阶段可用：未进入 play 或已关闭时抛 `IllegalStateException`（带当前状态），
  坐标/角度非有限值时抛 `IllegalArgumentException`。

### 2.2 协议层（`protocol-core`）

- `Movement`：把姿态校验与“最小包选择”独立成不依赖网络的对象，可直接单测。
- `LocalPose`：本端声明的位置+朝向+落地标记，不可变；用 `AtomicReference` 整体替换。
  网络线程（服务端同步/传送）与调用线程（上行）都会写，最后写入者胜出。
- `ProtocolEvent.PositionSent`：本端已声明的事实，与会话 Actor 的 `PositionUpdated`（服务端下发的
  权威坐标）区分开——服务端**接受**移动时不回包，本地状态只能由本端推进。

### 2.3 包选择规则

| 变化 | 包 |
| --- | --- |
| 坐标 + 朝向 | `pos_rot`（一个包，不拆两个：拆开会先让服务端看到“新坐标配旧朝向”） |
| 只有坐标 | `pos` |
| 只有朝向 | `rot` |
| 只有落地标记 | `status_only` |
| 都没有 | 不发包 |

`horizontalCollision` 恒为 `false`：无头客户端不做碰撞检测，报 true 等于请服务端替本端减速。

### 2.4 验证

- `MovementTest`（9 例）：五种变化组合各选什么包、落地标记随坐标包一起上报、永不声明水平碰撞、
  非有限坐标与角度被拒、角度不做归一化。
- `ClientSessionTest.移动与转向服务端可见`：
  - 服务端 `PlayerMoveEvent` 里读到的目标坐标与客户端声明逐项一致（`pos_rot` 路径）；
  - 仅转向后服务端朝向更新、位置不变（`rot` 包不带坐标）；
  - 服务端强制传送后客户端快照换成服务端坐标，并能从新坐标继续移动；
  - 非法坐标被拒且会话仍在 play；关闭后调用被拒。
- CLI 现场（`--walk 2`）：客户端 `event=move.sent x=1.0 … x=2.5`，服务端
  `event=player.move name=WalkBot x=1.0 … x=2.5`，步数与坐标两侧对齐，没有出现修正包。

## 3. 关键取舍

1. **不做本地物理与预测**。调用方给什么坐标就发什么；服务端不同意时下位置同步/传送，
   客户端快照被覆盖。库里没有方块碰撞、重力或速度积分，那属于下游客户端。
2. **本地姿态与请求同步推进**。发送后立即把自己记录的位置改成目标值并上报 `PositionSent`，
   否则“发出去了但本地还停在原地”，下一次差分会一直按旧基准算。
3. **快照语义写清楚**：`Session.world.position` 表示“本端声明的位置”，服务端纠正时覆盖；
   它不等于“服务端确认过的坐标”——服务端接受移动本来就没有确认可等。
4. **移动不进事件流**。每步移动只更新快照，不发 `ClientEvent`：调用方就是发起者，
   再回一个事件等于把同一件事说两遍。需要逐帧位置的渲染方读 `Session.world` 或自己按事件维护视图。
5. **不设坐标上限**。只挡 NaN/无穷；“太远该不该拒绝”是服务端的判断（Minestom 会踢人），
   在本层加任意上限会让合法的远征类玩法失效。

- 方块交互（挖掘、放置、使用物品）。
