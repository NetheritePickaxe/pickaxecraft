# M4n：实体交互（攻击 / 交互 / 挥手）

## 目标

客户端能对实体出手：攻击（左键）、交互（右键）、挥手（动画）。挖方块和放方块之后，
「可使用的客户端库」剩下的最后一种上手动作。

## 协议事实

- 26.2 把**攻击**从交互包里拆成了独立的 `attack` 包（只有实体 id）；交互包只剩
  「手 + 交互点 + 是否潜行」。协议里交互点用 lpVec3 编码，零向量紧凑成一个字节。
- **攻击没有回执包**：目标不存在或不在视野里时服务端静默忽略（Minestom
  `UseEntityListener` 的 `invalidUse` 提前返回）；打中了，结果以伤害事件包
  （`damage_event`）与实体状态变化体现。「成功没有回执」模式的第四例。
- 挥手是纯视觉：原版客户端攻击时总是挥一下主手，本库把它做成 `attack` 的默认伴随行为，
  也可单独调用。
- 交互点（`interactAt`）用于铠甲架部位判定之类的场景；Minestom 对有无交互点的处理一致。
  两个方法都保留是为了忠实于协议，不替调用方做取舍。

## 服务端侧（Minestom）

- 攻击只触发 `EntityAttackEvent`，**不自动结算伤害**——那是玩法逻辑。harness 在监听器里
  补一次固定伤害（`DamageType.PLAYER_ATTACK`，3 点），让两侧都有证据。
- 交互触发 `PlayerEntityInteractEvent`，事件里带手与交互点。

## 测试门控

- 联调用例：生成一只僵尸（`EntityCreature`），攻击它——服务端事件登记事实、僵尸血量下降、
  客户端收到 `EntityDamaged`；再右键它——服务端登记交互事实。两侧对账。
- 攻击不在视野里的实体没有服务端事实可等——这是协议形状决定的，不做「拒绝」用例。
